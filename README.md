# МояКарта 2.0 — дипломная версия

Карта личных и общих мест: метки с категориями, фото, комментариями и лайками, друзья и приватность. Выросла из курсового проекта (архив лежит в `public/` и больше не публикуется).

| Слой | Технология |
| --- | --- |
| Фронтенд | Vite 8, React 19, TypeScript, React Router 7 |
| Бэкенд и БД | Supabase: Postgres, Auth, Realtime, Storage |
| Карта | Яндекс.Карты JS API 2.1 при наличии ключа, иначе OpenStreetMap; кластеризация в обоих случаях |
| Хостинг | Firebase Hosting (`mycard-ae62b`) |

Своей серверной логики нет: доступ к данным ограничен RLS-политиками в базе, поэтому браузер работает с Supabase напрямую.

**Живой сайт:** <https://mycard-ae62b.web.app>

## Что понадобится

- Node.js **22.12+** (требование Vite 8).
- Проект Supabase с применёнными миграциями — см. [supabase/README.md](supabase/README.md).
- Ключ **JavaScript API Яндекс.Карт** — необязателен. Без него приложение автоматически переключается на OpenStreetMap с кластеризацией, так что карта работает всегда. Старый ключ из курсового проекта недействителен (`Invalid API key`); новый берётся в [кабинете разработчика](https://developer.tech.yandex.ru/), в ограничениях укажите `localhost` и домен Firebase.
- Доступ к проекту Firebase `mycard-ae62b` для деплоя.

## Быстрый старт

```bash
cd app
npm install          # или из корня: npm run install:app
cp .env.example .env.local   # подставить URL и publishable-ключ
npm run dev                  # http://localhost:5173
```

Создание базы и миграции — в [supabase/README.md](supabase/README.md). Без `.env.local` приложение запустится, но покажет баннер «Supabase не настроен».

Из корня проекта:

```bash
npm run dev        # тот же Vite-сервер
npm run build      # сборка в app/dist
npm run typecheck  # tsc --noEmit
npm run test:app   # юнит-тесты компонентов (Vitest + Testing Library)
npm run test:db    # миграции + RLS на локальном Postgres (PGlite)
npm run deploy     # сборка + деплой на Firebase Hosting
```

## Деплой

```bash
npx firebase-tools@15 login   # один раз, под вашим аккаунтом
npm run deploy                # сборка app/dist → hosting:production
```

Деплой идёт в target `production` (`.firebaserc` → сайт `mycard-ae62b`). Чтобы посмотреть сборку до публикации в прод, используйте временный канал:

```bash
npm run deploy:preview   # hosting:channel:deploy, ссылка будет в выводе
```

Не деплойте, пока пуст `app/.env.local`: соберётся конфигурация-заглушка, и сайт покажет баннер «Supabase не настроен» вместо карты.

```
│   ├── features/auth/  # AuthProvider: сессия, профиль, вход/регистрация

│   ├── pages/          # карта, вход, регистрация, 404
│   ├── styles/         # токены дизайна и компоненты
│   └── types/          # типы строк БД
├── static/             # favicon и прочая статика Vite
└── index.html
supabase/
├── migrations/         # схема, RLS, Storage, Realtime, категории
└── README.md           # как поднять базу
public/                 # архив курсовой версии, в сборку не попадает
```

`app/vite.config.ts` специально указывает `publicDir: 'static'`, чтобы старый сайт из `public/` не попал в бандл.

## Модель данных

`profiles` → `markers` → (`marker_photos`, `comments`, `likes`), плюс `categories` (справочник) и `friendships` (заявки в друзья).

Видимость метки задаётся полем `visibility`:

- `public` — видна всем, включая гостей;
- `friends` — только владельцу и принятым друзьям;
- `private` — только владельцу.

Правило видимости реализовано один раз — в `public.can_view_marker()`. Его используют политики меток, комментариев, лайков и фото, поэтому приватная метка закрывает и файлы в Storage: они отдаются только по подписанным ссылкам.

## Что уже работает

- Карта с кластеризацией и автоподстройкой под фильтр.
- Категории и фильтр по ним, поиск по названию и описанию (с задержкой 300 мс, триграммные индексы в БД).
- Создание метки кликом по карте и редактирование своей метки: название, категория, место, описание, видимость.
- Панель метки с автором, категорией, координатами; удаление своей метки.
- Фото меток: загрузка в приватный bucket, подписанные ссылки, удаление.
- Комментарии и лайки прямо в панели метки.
- Друзья: поиск людей по нику, заявки, принятие/отклонение, удаление.
- Страница профиля `/u/:username`: метки пользователя, редактирование своего профиля, закрытый профиль.
- Аватары: загрузка в публичный bucket, замена и удаление.
- Регистрация и вход, автосоздание профиля триггером, подтверждение почты.
- Восстановление пароля: письмо со ссылкой и страница установки нового пароля.
- Realtime: изменения меток подтягиваются без перезагрузки.

## Безопасность

- Публичный ключ в браузере — норма; доступ ограничивают RLS-политики, а не секретность ключа.
- `secret`-ключ (`sb_secret_...`) в клиент не попадает никогда.
- `profiles` не хранит почту: она остаётся в `auth.users` и не отдаётся другим.
- Storage-бакет приватный, путь файла привязан к владельцу и метке.
